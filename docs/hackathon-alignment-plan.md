# CityPlay AI 赛事对齐与调整方案

分析日期：2026-10-14。依据用户提供的赛事 Requirements、当前源码及真实数据价值对照。

## 判断

核心没有偏离：DeepSeek负责意图，Qloo真实实体/标签及Insights负责跨领域地点候选，工具调用与校验已有状态机。移除Qloo会失去候选来源。但“依赖一个API”不等于“展示了文化智能的差异”；目前更像带自然语言入口的地点检索器，评委不易看见文化口味如何影响结果。

已验证的证据：纽约音乐人＋书店组合与同范围普通书店筛选的top10仅重合1个，符合目标类别6个；普通书店组符合类别8个。改变结果不等于提高用户满意度。尚未完成LLM-only对照，不能声称已经更准确、个性化更强或提升了某个百分比。

## 产品重新聚焦

定位：**从文化口味出发，发现城市中值得了解的地方。**

主输入优先是具体音乐人、电影、书籍等文化实体，场所类别是本次目标；直接地点类别查询可保留为次要入口。“猜你喜欢”作为可选辅助，只有宽泛生活习惯时可以帮助补充具体文化锚点；不能将LLM推测的体验动机宣称为Qloo验证的个人特征。

纽约作为已验证主演示范围，上海保留实验模式并真实说明覆盖限制。地图保留，承担地点可视化，停止将地图细节当作本轮主创新方向。对漂流、蹦极、全部本地活动、实时场次和预约能力不做超出证据的承诺。

评委路径：不注册即可选择/填写文化兴趣 → 系统给出简短探索方案 → Qloo识别实体并在目标类别中检索 → 类别/位置检查 → 少量真实候选＋地图 → 展示采用的文化信号与工具过程 → 用户更换文化兴趣或给出反馈，代理重新计划。

## 修改优先级

### P0：让Qloo的作用可见

1. `web/index.html`、`web/app.js`：以“文化口味→城市探索”为主文案；文化实体、探索方向、地图三者形成清楚的一条链。具体实体入口与宽泛生活习惯入口分开提示，但保持可跳过、少步骤。
2. `src/cityplay/engine.py`：结果增加本轮实际实体/标签、目标类别、Qloo请求方式和同请求相对顺序等可呈现依据；先围绕文化关联与用户目标组织候选，网站名称证据作为独立核验状态，避免网站字段的多少遮蔽口味差异。
3. 卡片解释改为每个候选的真实来源与筛选依据。没有关系解释数据时，不能编造“复古氛围”“电影感”等原因，不将affinity写成个人喜欢概率。若另测Qloo解释能力，必须先核验当前Key实际返回。
4. 提供可选“文化口味推荐 / 同类别无口味基线”对照，默认只加载口味方案，用户展开对照时再调用，限制费用。两个面板必须同中心、半径、目标类别、返回上限和同一套过滤；不要把基线故意做差。

### P1：让代理完成探索，而非退回用户填表

1. 复用现有状态机增加明晰的探索计划：文化锚点、场所方向、地理范围及未知条件。
2. 类别归一化依据真实返回扩展Museum子类、Jazz club等；逐项验证，不能为了出结果混入录音室/办公地点。
3. 空结果仅在有授权且明确显示调整时做有限重试，如改标签检索策略、舍弃未匹配信号；明确预算、排除项与用户规定范围不能静默放宽。
4. 提供轻量反馈用于本次重排/重新检索，并区分兴趣信号与实际体验后的偏好。长期学习仍非本轮必要目标。

### P0交付：公开可运行

1. `src/cityplay/web.py`：另设生产启动/配置；当前Host/Origin/绑定地址只允许localhost，不能仅把进程放到云上或开放端口就算部署。
2. 公开服务使用HTTPS、受控域名Origin、服务端环境凭据、共享限额与并发保护；评委无需自行提供Key。Qloo/DeepSeek失败必须明确，禁止假结果降级。
3. 当前进程120次Qloo尝试上限耗尽后会阻止所有新请求，评审访问前需改成可管理的配额策略；不能直接去掉保护。评审期间Key有效期与剩余额度需另核对。
4. 真实响应/私有画像文件、.env.local、截图、临时日志不进入公开仓库。只公开合成fixtures、聚合验证方法与源代码；保留Leaflet许可证。
5. 更新README、项目级LICENSE、公开仓库链接、在线演示链接及赛事文本描述。未实际创建外部资源前，不写“已经公开部署”。

## 差异化验证标准

至少使用多组文化锚点，覆盖音乐/电影及两个已验证场所方向。在固定城市、范围和类别下比较：

- Qloo文化信号方案；
- Qloo同类别但不带文化信号的方案（检验taste信号增量）；
- DeepSeek-only方案（相同用户输入和输出要求）。

LLM-only的输出单独标识为对照，不能进入正式地图推荐的事实来源。通过独立核验或明确记录“不确定”来比较实体/地点可解析性、地址坐标准确性、类别匹配、用户盲评相关性、调用延迟与失败率。不存在的地点不能因为语言流畅而算合格；两个方案采用相同评分标准。没有可靠参考坐标时不计算定位准确率。未做足样本和用户研究时，只报告观测结果，不声称统计显著或用户偏好提升。

验收不只是两组列表不同：评委应能够看到改变文化锚点会改变同类别探索结果，同时这些结果都保持可追溯、符合场所与范围要求。公开演示的入口、核心接口、手机地图和空结果恢复均应在全新浏览器会话中可用。

## 范围收缩

这轮保留文化解析、Qloo跨领域检索、轻量确认、地图和可解释决策。暂停扩大上海所有本地活动、复杂注册/长期画像、预约/门票/实时营业系统、无依据的刺激度/情绪画像。目标是一个评委能完成并理解“为什么必须有Qloo”的闭环，而不是功能最多的本地生活平台。
