# 平行人生：文化口味驱动的城市探索

2026-10-15。产品方向从单次地点问答转为可比较、可纠正的探索版本。外部部署仍暂缓。

## 已实现

1. 熟悉的我：依据用户确认的最多三个文化兴趣查询地点。
2. 邻近的我：以已解析的兴趣作为 Qloo 信号查询音乐人，从返回中选择不等于原输入的真实对象，重新解析校验实体 ID，再以该对象查询地点。展示原兴趣 → 文化桥梁 → 地点的两步路径。并不保证用户此前不知道此对象。
3. 另一种我：用户主动填写音乐人、电影或书籍新起点；经过同样解析和地点检查形成第三个版本。无需把尝试方向保存为已有爱好。没有新起点时仅展示待选择入口，不生成隐藏人格。

各版本保留同一城市中心、半径、类别、排除项及硬性预算/时间/营业要求；没有证据的硬性条件仍会阻止候选。版本独立保存并通过服务端当前 draft 校验进行激活；浏览器不能注入任意地图地点。地点可在不同版本重复出现，不以去重制造个性化差异。

## Agent 的具体决策

解析并确认口味 → 查询熟悉候选 → 寻找真实文化桥梁 → 校验桥梁 ID → 重新检索地点 → 应用现实条件检查 → 呈现版本和证据。桥梁查询失败时保留熟悉版本；不以 LLM 生成的作品或地点替代。配额继续限制为会话 40 次 Qloo 网络尝试，单次扩展最多增加 14 次上限。

反馈保留当前版本的文化起点，跳过已反馈地点；距离反馈改变候选排序。再次激活其他版本时仍应用当前会话的地点排除。反馈不自动扩大成某类文化偏好的否定。

## 真实接口探测

Hackathon 服务真实查询 Miles Davis 音乐人实体，再使用 /v2/insights 的 artist 输出与 feature.explainability=true，实际得到 John Coltrane、Charlie Parker、Thelonious Monk，均为 artist 实体且含解释字段。原始返回存放 .qloo-private/parallel-cultural-hop.json，不提交公开仓库。已验证该样本的实体关联，不把它当作所有输入的覆盖承诺。

## 产品边界

版本表示探索方向，不是心理人格或已核验的一日行程。两跳贡献分不能相乘为喜欢概率。用户是否喜欢、地点实时营业、路程时间和总费用均不能由文化关联推导。暂未生成路线或预约安排；地图仅显示候选。后续应先开展版本选择与体验反馈评估，再考虑跨会话记忆和行程编排。

## 三版本链路实测

纽约书店、10km，原兴趣 Miles Davis；邻近桥梁实际选择 John Coltrane；主动新起点 Björk。三版本均为 partial，各有 3 个类别/坐标/地址通过检查的地点候选，8 次网络尝试。此次没有额外抓取网站（max_checks=0），网站和运营条件均未独立核实。原始证据仅在 .qloo-private/parallel-lives-validation.json。

新增直接文化名字输入入口，由服务端严格校验并生成待确认意图，不依赖模型解析。浏览器自然语言测试遇到外部模型超时，因此该入口同时确保核心 Qloo 体验可独立使用；不把该故障归因于 Qloo。

浏览器端已完成直接起点 → 确认 → 自动生成熟悉/邻近版本 → 激活邻近版本 → 输入 Björk → 生成并激活第三版本。熟悉版和邻近版各 3 个地点，其中共享 2 个；第三版实际展示 Printed Matter、Dashwood Books、Albertine。允许真实重合，不以虚构差异制造“平行人生”。73 项 Python 测试、6 项前端探索流程测试通过。截图为私有验证文件 .qloo-private/stage3/parallel-lives.jpg。
