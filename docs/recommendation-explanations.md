# 可解释文化探索与会话反馈

2026-10-14 本地实现，外部部署仍暂缓。

## 真实接口验证

向 Hackathon 服务进行两组请求，共 5 次网络调用：单实体 Miles Davis，以及 Miles Davis + Blade Runner。每组 Insights 请求 take=3、纽约中心半径 10km，启用 feature.explainability=true；原始返回安全保存在 .qloo-private/explainability-probe.json 和 explainability-multiple.json，不提交源码仓库。

两组均返回 query.explainability。候选级结构为 query.explainability["signal.interests.entities"]，每项有 entity_id 和 score。单实体三条贡献分均为 1；双实体三条约为 0.538/0.462、0.523/0.477、0.531/0.469。这些是信号贡献，不是用户满意度概率；没有证明地点氛围、性格特征或因果原因。未验证标签贡献结构，因此不解析或假定标签解释。

## 产品实现

每张卡片显示实际贡献者及可展开贡献分、匹配的场所方向、到所选中心的距离。只接受本轮已解析实体 ID 和有限的 0–1 数值；解释缺失或结构变化时明确说明不足。

用户可从综合口味切换到已确认的单项兴趣，保留类别、范围和硬性条件。切换后重新检索，并继续排除本次会话已反馈的地点。此功能用于体验不同探索方向，不构成严格偏好评测。

反馈分为“这次没兴趣”“太远”“体验过，不喜欢”。三者分别记录；地点在会话内排除。“太远”额外在 Qloo 候选中优先考虑到所选中心的距离；不承诺路程更短或有更近候选。其他反馈不扩展为整类文化偏好的否定。每次最多检索 10 条/类别，检查 6 条、展示 3 条；保持请求配额与严格过滤。

## 边界和后续

反馈目前只在服务端会话中保存；尚无跨会话记忆、相似活动负向推断、长期权重学习和反馈原因追问。客户端不得反馈未展示的地点。解释不能替代用户对体验的评价。下一步应根据真实反馈建立可撤销的个人偏好记录，再评估相似场所调整；不能直接将本地排除功能称为已学会个人喜好。

## 本地验收

69 项 Python 测试及 6 项前端探索策略测试通过。真实浏览器输入两个文化实体并探索纽约书店，展示 3 个候选及各自贡献分；其中一个候选贡献分约 0.51 / 0.49。对 6.7km 的候选点击“太远”后，该地点被排除，当前展示距离变为约 0.3、0.5、1.3km，原有两个文化兴趣仍保留。此结果是单次运行观测，不是普遍效果承诺。

## 2026-10-15 自动匹配与空结果修正

前端此前在名称不相同时直接采用同类型第一候选，可能将《鲁滨孙漂流记》替换成无关书籍。已取消该回退：仅规范化 Unicode、空白和常用书名/人名分隔符后唯一同名且类型相符的候选自动采用。没有已核实别名映射的跨语言标题不能仅凭排序认定为同一作品；未确认项本轮略过，原输入保持。显式用户选择仍可通过已有候选选择流程完成。

移除逐项自动匹配诊断通知。空结果主界面显示保留口味及下一步操作，不展示候选计数和技术过滤原因；真实诊断仍在服务端私有证据中，不补造地点。新增前端回归场景覆盖无关书籍、中文空格规范化和重名歧义；9 项探索策略场景通过。
