# 猜你喜欢 MVP

> 2026-10-15 已重建为文化卡片流程，当前实现见 [文化卡片重建](taste-cards.md)。以下保留旧问卷及画像流程的历史记录。

## 现有系统调查与取舍

原入口为 `web/index.html` 的 `#query` 文本框，经 `app.js` 调用 `/api/parse`，DeepSeek JSON 解析为 `Intent`，用户确认后 `/api/discover` 进入 Qloo 检索和证据过滤。当前没有账户、用户资料数据库或长期画像读取接口；只有浏览器会话和本地私有证据文件。新增功能沿用 Python 标准库服务、DeepSeekClient、会话/CSRF、私有存储，未引入框架或修改推荐排序。

## 实现与状态

入口完全可选，原文本框仍可直接使用。四道逐题卡片复用所选城市，覆盖明确喜欢的日常活动、想探索的场所、文化作品/风格和尚未尝试的方向。支持多选、自定义答案、返回、跳过、退出和进度。目标约1–2分钟；尚未做真实用户完成时间研究。动态追问延后。

2026-10-14 名称和题目同步调整：从“爱好画像”转为探索灵感，移除体验投入和社交节奏两题，移除漂流等未接入选项。鼓励补充具体音乐人、作品名，但不强制填写。周末意向和新体验只能进入待尝试分组，不能被模型升级为已有喜好；后端检查引用片段被截短的情况。草稿不是 Qloo 验证结果，确认后才进入真实匹配流程。现有 API 和私有保存格式继续兼容旧答案。

`问答 → /api/guess 异步任务 → 内存草稿 → 用户编辑并逐项勾选 → /api/profile/confirm → 私有确认文件 + 合并原文本框 → 原解析/确认/推荐流程`。

模型仅输出名称、简介和四组标签；每项包含来源、定性置信度、理由及答案原文引用。服务端校验字段白名单、条数、长度、来源和原文引用。已有兴趣要求名称来自原文，愿望/社交题不能作为已有爱好的依据；潜在兴趣和动机固定为 AI 推测。明确排斥项需要否定语句。此校验不能证明模型的每项语义判断正确，仍须用户确认。标签ID由服务端分配，不是 Qloo ID，也不代表 Qloo 覆盖这些活动。

现有兴趣默认勾选，推测项默认不选；支持编辑类型/简介/标签，删除、补充、部分确认及重新生成。改名记录 `user_edit` 并保留来源证据。用户补充记录 `user_input`，没有模型置信度。潜在标签不能通过客户端改组冒充已有兴趣。

确认保留原输入字节，新增内容以“喜欢”“想尝试”“避免”分别写入；同类按大小写/空白归一及字面匹配去重，不进行语义同义词合并。动机单独保存，暂不参与排序。原输入与新选择若矛盾，不改写原输入，由后续需求确认解决；同次选择出现正负同名标签则拒绝确认。

## 隐私、错误与存储

原问答不写入请求日志或生成证据文件，未确认草稿只保留在限时会话内存。已勾选标签及其引用证据在确认后存入 `.qloo-private/stage3/*.profile.json`，权限0600、目录0700、忽略提交。该本地记录尚不提供跨设备同步或重启恢复入口，不构成账户数据库。用户关闭页面会丢失尚未确认的问答；界面中途退出再进入保留当前页面的答案。

模型凭据仅服务端读取；已知凭据/明显联系方式在发送前拒绝。复用30秒请求超时，最多两次生成尝试，仅异常结构和临时网络错误重试，鉴权失败不重试。画像输出上限2600 tokens，原需求解析仍1200。失败保留页面答案/编辑内容；重复确认同一请求返回同一记录，变更已确认草稿须重新生成；重新生成不覆盖已确认记录。生成过程中退出仍可编辑主输入框，正在进行的服务端任务会暂时占用当前会话的任务槽位。

## 后续体验反馈方向

动态追问、长期兴趣学习、反馈修正和排序升级均未在本轮实现。建议后续分别记录“想尝试”“实际体验后喜欢/不喜欢”，并附活动实体、时间、画像版本和可选原因。漂流第一次心动应属于潜在兴趣；体验后不喜欢，先询问是强度、水环境、拥挤、天气还是运营服务，不应把单次体验等价为永久厌恶所有水上活动。形成可解释的修正建议，让用户确认、撤销和删除，再应用到推荐。反馈没有收集前不得声称系统已经理解真实体验偏好。

## 需求解析稳定性修正（2026-10-14）

针对“看电影、公园散步、旅行；想尝试漂流、蹦极、社交活动”出现 `INVALID_MODEL_INTENT` 的情况，调整了通用兴趣映射提示：泛指看电影应作为概念，不能输出名称为空的电影实体。模型JSON/Schema异常或可重试的临时服务故障最多追加一次请求；鉴权和其他不可重试服务错误直接返回。校验失败响应携带服务端定义的字段路径和原因，私有错误记录不保存原始模型输出或需求文本。页面保留原输入并显示具体兴趣/条件字段。

兴趣超过本轮3个信号以及部分超出场所检索范围的活动，进入既有用户确认链路；不增加Qloo字段或虚构活动覆盖。确定性能力提示目前覆盖漂流、蹦极、露营、陶艺、舞蹈和社交活动，其余方向依赖模型澄清，尚不是完整活动分类系统。兴趣上限提示识别“喜欢/想尝试”格式及模型澄清，其余自然语言列表由模型识别。模型澄清与确定性提示按明确文字匹配去重，不能保证所有同义表达都去重。

新增 `tests/test_intent_recovery.py` 和HTTP错误详情测试，验证重试上限、鉴权不重试、字段诊断、坏类型、原查询保留、超出能力提示以及避免重复。总计54项自动化测试。真实浏览器输入已成功进入需求确认页，兴趣字段为movies、park walking、travel；漂流、蹦极、社交活动显示能力限制提示。概念是否被Qloo标签解析成功仍须后续真实检索，本轮验证只证明需求解析和确认恢复。

最新预览服务已重启并保持运行，地址仍为 `http://127.0.0.1:8787/`。

真实复测中还发现模型可能把页面“纽约附近”误解为“必须在市界内”。增加针对页面区域上下文的校正：原描述没有市界/行政区域限制时，不自动引入strict_city；明确市内要求仍保留。

## 默认方案与自动标签匹配（2026-10-14）

用户授权系统整理可执行方案后，解释性/待澄清提示默认不再作为强制检索门槛；确认区说明未明确或未接入的要求本轮暂不执行，用户可恢复勾选。市界和未到访保证默认改为所选附近范围及探索候选，并在确认区显示调整。明确数值预算、时间、营业要求和排除项保留，不因为没有结果而自动放宽。

点击确认后，基于真实Qloo候选自动匹配兴趣：有指定实体类型时先过滤类型，优先同名，否则采用返回顺序中的首个可用候选。没有匹配的兴趣仅在本轮略过；不会用杜撰的兴趣替代，也不改变正式画像。自动继续最多4次，以限制请求数；超限仍提供预选候选及明确操作按钮。剩余非候选问题展示实际原因，并提供“采用可执行方案”按钮，明确说明哪些保证将放宽。调用额度限制仍可能中止本轮检索。

自动选择属于启发式，不代表已证明用户喜欢该实体或标签。页面展示所采用的候选和本轮略过项；自动修改后的检索意图仅在会话内用于本次探索，原输入保留。

验证：54项Python测试通过；`node tests/test_exploration_policy.cjs` 的6个场景通过，覆盖真实候选ID选择、类型匹配、略过未匹配兴趣、保留预算/营业条件、原意图不变、无兴趣结束、非候选问题不无限自动重试。JS语法通过。原六项兴趣真实浏览器测试仅点击一次确认，自动选择Walking和Travel候选，返回1个真实地点候选，未再要求逐项确认。测试结果不证明漂流、蹦极或活动场次已经接入。预览服务已重新启动。
